## 2. Thiết kế

- `Item.min_stock_level`: PositiveIntegerField, default 0, verbose_name “Tồn tối thiểu”; form/model nhận số nguyên 0..2147483647 để tương thích PostgreSQL integer. DB chặn âm; không nới bất kỳ constraint DP02/TU03 nào.
- `ItemQuerySet.needs_restock(self)`: lọc `min_stock_level > 0 AND quantity <= min_stock_level`.
- `ItemQuerySet.restock_list(self)`: tải category/vendor cùng truy vấn, annotate thiếu = min − quantity, order `-shortage,name,pk`.
- `Item.needs_restock`, `stock_shortage`, `suggested_order_qty`: property phục vụ giao diện/Excel; tính đề xuất bằng số nguyên Python để tránh tràn integer SQL khi nhân đôi ngưỡng.
- `LowStockListView.get_queryset(self)`: danh sách yêu cầu đăng nhập, phân trang 25 dòng.
- `export_low_stock_to_excel(request)`: yêu cầu đăng nhập, dùng cùng queryset không phân trang; openpyxl và `to_excel_datetime` của HC02/TU03, ZoneInfo Asia/Ho_Chi_Minh.
- `PurchaseCreateView.get_initial(self)`: kiểm tra ID từ GET, chọn sẵn mặt hàng hợp lệ; không ghi DB, không thay POST đã bind.
- `ItemForm.clean_min_stock_level(self)`: client cũ thiếu key giữ ngưỡng cũ/default 0; người dùng để trống trường hiển thị thì đặt 0. `save(self,commit=True)` bỏ quantity khỏi metadata nếu chỉ đổi ngưỡng và tồn không thay đổi trên form, tránh ghi đè một thay đổi kho xen giữa validate/save.

Luồng:
1. Đăng nhập, sửa sản phẩm, lưu ngưỡng qua ItemForm → save_item.
2. Queryset lọc trực tiếp tồn hiện tại, không lưu cache trạng thái cần nhập.
3. Dashboard đếm cùng điều kiện; danh sách/Excel dùng cùng thứ tự.
4. Người dùng mở phiếu nhập qua `?item=<id>`, xác nhận giá và số lượng.
5. Bán/nhập vẫn qua dịch vụ DP01; lần tải trang sau tự phản ánh trạng thái mới.
